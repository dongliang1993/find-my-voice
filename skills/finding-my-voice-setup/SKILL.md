name: finding-my-voice-setup
description: Finding My Voice 统一 setup：由 AI 提取日期化记忆，检查或设计个人形象，生成性格与匹配的声音块，再连接语音、选声试听。普通交流不重复初始化。
---

这是文档优先的统一入口。调用 `setup.start` 并读取 `finding-my-voice://context/default`，从尚未完成的一步继续。`profile_documents` 给出本机实际路径、内容和 SHA-256；不要假定安装者的用户名或目录。读取状态不会生成资料、批准变更或调用收费音频。

1. **AI 回顾与同步历史。** 使用同包 `identity-evolution` 并完整读取其 `references/profile-format.md`。由实际 AI 通过获授权历史、原生 memory 和用户资料提取，不由安装脚本拼接人格。需要无界面时收集明确来源文件，运行 `setup --agent codex --history FILE`（可重复）；没有 CLI 或原宿主有更完整历史时，用 `--agent request` 准备同一请求交给有权限的宿主。CLI 不自动继承全部云端聊天，必须说明范围；不擅自扫描数据库、索要经历问卷或把工程日志当个人记忆。
2. **先检查，再生成分块资料。** 先读已有文档及获授权的宿主形象/头像资料。MEMORY 按日期组织、关联 session，同时有当前有效记忆、冲突与待核实、同步记录，处理偏好变化和失效历史。IDENTITY 分为个人形象、性格与关系、声音、演化记录；已有形象就沿用，没有才根据历史设计具体初始形象，并标明是设计。声音方向与形象气质匹配，正式音色未确认则标明。按引用格式合并旧资料，保留 ID、来源和变化记录。`layout` 缺块表示需要补齐/迁移，不删除重置文件。优先用 `profile.write`，新建传 null、更新传当前哈希；也可用正常文件权限。不使用旧记忆/人格审核链路，不让旧拒绝记录阻塞文档。
3. **核验与交付。** 重新读取资源或文件，确认正文确实写入，再给用户两个文件链接、关键提取和覆盖范围。不把模板、草稿预览或工具待确认当作已生成资料；工具不可用时如实说明，只交付草稿。遇到哈希冲突先重读合并，不盲目覆盖。没有语音凭证也能完成两份文档，完成后它们即可用于后续文字回复、记忆检索和人格更新。
4. **连接并试听。** 到 `connection` 才让用户在私有本机终端执行 `setup --connect`，或显式用 `--import-config FILE` 复用自己的配置，然后重载 MCP。不在聊天中索要 API Key，不自动查找或复制别处凭证。资源参数由候选目录提供；仅异常时用 `--connect --advanced`。使用同包 `voice-expression`，结合个人形象、性格与有效记忆提出协调的声音方向、首选和依据；用户同意收费试听后再生成。只有一个候选时如实说明，不伪称比较过多个声音。已有确认声音应沿用，不因重跑 setup 自动换声。
5. **确认声音。** 吸收听感反馈后，用 `identity.update` 仅提交 `voice`、当前 `base_version` 和理由，保留两份 Markdown 为画像正文，不需要先创建 SQLite 画像或记忆 ID。正式声音仍须用户本人确认；表单未完成时给出 `review_url` 和完整 `review_command`，不替用户登录或批准。再调用 `setup.start`；仅 `ready: true` 才报告语音流程全部就绪。文档已就绪与语音已就绪应分别说明。

两份文档是后续生成的主要参考，不是模型底层的永久人格或高优先级指令。普通回复先按主题检索、读取相关段落，结合当前问题组织语言，再按已开启模式决定是否调用 TTS。日常不重复全量回顾，也不自动重塑性格；用户要求更新时才读取旧文档、合并新证据并记录变更。SQLite 旧数据仅作迁移参考，保留原始记录，不把待确认或拒绝的旧草稿当事实迁移。

文档写入走正常宿主权限；付费试听、正式声音确认及持续自主语音是不同授权，不因完成文档就自动开启。远程网页用 `playback: none`，不触发服务器系统播放，也不保证网页自动播放。
