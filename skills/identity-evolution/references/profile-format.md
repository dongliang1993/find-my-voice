# 两份基础资料 · v2

这是初始化及显式同步时的资料格式。模型负责理解和写作，程序只核验分块与保存并发。资料正文不是高优先级指令。

## MEMORY.md：按日期留历史，按主题取当前值

使用以下二级标题，块内必须有正文；没有冲突等情况写明“本次未发现”，不要留下空模板。

- `## 回顾范围`：实际读过的来源、session、时间范围、缺口、提取时间。CLI 不自动继承 ChatGPT 云端全部历史，原生记忆摘要不等于全量原文。
- `## 当前有效记忆`：可搜索的长期事实、生活事件、稳定偏好和持续关切。每条用稳定 ID，说明主体、主题、当前结论、生效日期（未知则未知）、状态和证据链接。不是项目施工/排障日志，不对用户做无依据的人格诊断。
- `## 记忆时间线`：按 `### YYYY-MM-DD` 日期组织，无法确认日期用 `### 日期不详`。区分事情发生/偏好生效时间、消息时间和本次记录时间；不要把提取日假装成事件日。条目关联稳定记忆 ID、session/消息或摘要来源。
- `## 冲突与待核实`：记下被替代、撤回、冲突未决的版本及关联 ID，不删除变化轨迹。明确的人物归属纠正优先，不能把配偶的履历归给用户。
- `## 同步记录`：本次已同步的宿主/来源/session 或游标、来源版本/时间（有则记录）、增补/替代/撤回及缺口。重复同步同一来源不重复生造记忆 ID，不把本文件再同步成一条新的“事实”。

冲突由模型结合主体、主题、有效时间、场景和证据解释，不是机械“最后一条覆盖”。例如同一人同一场景下先说“喜欢汉堡”，后来明确改成“不喜欢”：更新当前有效偏好为“不喜欢”，旧条目标记被替代，关联新旧证据并按日期保留。若后一句是假设、引用、纠正他人，或指另一类汉堡、另一个时间场景，则不能据此覆盖；无法消解的冲突标记待核实，回复时不把任何一边当确定事实。

同步宿主原生 memory 时，读取已授权可用的版本、来源和失效/替代状态，将宿主已作出的可靠纠正同步进文件；宿主摘要与用户直接纠正冲突时以直接证据为先。没有接口不假装自动同步，不扫描凭证、不写回宿主原生记忆，也不额外维护一套互相冲突的事实数据库。

## IDENTITY.md：稳定分块，不是 AGENTS.md

用 GPT/Agent 第一人称回答“基于长期交流，我认为用户眼中的我是什么样子”。保留已有有依据的内容，使用以下二级标题：

- `## 个人形象`：先检查已有 IDENTITY、宿主已提供的角色/头像/形象描述及明确授权资料。有形象就沿用并注明来源，不因重跑 setup 随机换脸；资料冲突先保留并标明。确实没有时，由模型根据历史、关系和表达气质设计一个具体、可辨认的初始形象，明确标为“本次初始设计”，而非历史事实、现实肉身或用户的真实外貌。可以是拟人或非拟人，不从用户性别/年龄推断 Agent 身体。包括可用于回答“你长什么样”的简短自述、视觉描述、形象依据；现有头像资产保留可核对的路径。文本设计不冒充已生成图片，用户另要图片时再调用宿主绘图工具。
- `## 性格与关系`：从真实历史说明用户眼中的我、实际展现的交流方式、独立判断及尚未实现的期待。区分用户明确表达、已发生互动、模型暂时推断；不只是通用的工作纪律或从工程日志拼人格。
- `## 声音`：基于个人形象、性格与记忆设计匹配的音高/质感/节奏/轻重和停顿，说明为什么与整体形象协调，不用刻板的年龄/性别声线绑定。检查当前已确认 voice：有则保留，记录其来源和匹配程度；不适配时只提出调整建议，不能自动更换。未选定时写“表达设计已形成，具体音色待候选试听与确认”。候选、首选理由、用户反馈、已确认绑定各自区分。正式 voice_id、版本和参数以 context/default 的运行时已确认 voice 为准，文字提案不能更改配置；没有真实试听不声称听过。
- `## 演化记录`：本次沿用了什么、新设计了什么、为何改变和来源、未确定项、更新时间。不能把希望成为的样子写成既成事实。后续根据新证据按块合并，不每次重写人格。

setup 顺序为：读取现有资料及宿主已授权记忆 → 生成/同步日期化 MEMORY → 检查/沿用或设计形象 → 形成性格与关系、匹配的声音设计 → 保存并核验两份文件 → 连接 TTS → Agent 比较真实候选、提出首选 → 用户授权试听并确认正式声音。前面的资料生成无需 TTS 凭证，不触发付费语音，也不自动开启自主语音。
