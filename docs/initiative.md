# 主动：她为什么开口

> 主动性让她从一个工具变成一个“存在”。做不好，就会变成推送通知。

## 一条原则

**她每次主动开口，都要有一个能指名道姓的理由。**

“好久没聊了”不是理由，那是运营推送。“你周五的面试怎么样了”才是。

这条原则落到代码里，不是写在提示里求她遵守，而是结构上的硬约束：**规则决定什么时候允许开口，判断决定开不开口、为了什么开口。** 没有具体对象的候选，根本不会进入生成。

## 一、可以因为什么开口

按价值从高到低。每一种都必须是**具体的事**。

| 种类 | 例子 | 现状 |
|---|---|---|
| `followup` 跟进你说过的事 | “面试还顺利吗？” | 已有 |
| `echo` 延续她自己的念头 | “我还在想你昨天说的那片橙色的天。” | 已有 |
| `rhythm` 你常聊天的时段 | 下班时问一句今天怎么样 | 已有（仅“经常”档位） |
| 环境信号 | 深夜还在电脑前：“已经很晚了” | 待做 |

- **`followup`** 来自整理记忆时抽出的带时间事件。价值最高，也最能体现“记得你”。
  - 你自己先说了结果，这条就关掉；到期 48 小时内没机会问，就退场，不补问。
- **`echo`** 是最打动人、也最容易显得假的一类，所以规则最多：
  - **原料**：整理记忆时最多抽一句“让她印象深的画面或一句话”。关于痛苦、隐私、难过的事，或者别人的事，不抽。
  - **必须是原话**：抽出来的那句要能在你说过的某条消息里逐字找到，否则丢掉——改写过的句子是模型的话，不是你的；“你说过……”后面跟着你没说过的话，是 echo 最不能犯的错。那条消息的时间就是这句话的时间。
  - **时间窗**：至少隔 6 小时（同一晚再提，只是还在聊这件事），最多 48 小时（两天后就不是“还在想”了）。
  - **熟了才有**：你和她聊过的日子满 5 天之后才会出现。
  - **很少**：“偶尔”档位至少隔 5 天一次，“经常”至少隔 3 天。
  - **只提一次**：不管她说了还是放下了，都不会再回来。判断说“不”时也直接放下，因为被否掉的通常是这句话本身（太私人、太单薄），不是时机。
  - 开口时提到你的原话或那个画面，说她自己的念头，不变成提问。
- **`rhythm`** 只在“经常”档位允许。理由里写的是真实的时段（“周四傍晚 18 点”），不再一律叫“早上”；你今天晚些时候有安排（比如下午的面试），就挂在那件事上；没有的话，一句轻轻的问候也可以，但不编一件事出来。
- **优先级**：`followup` > `echo` > `rhythm`。被连续冷落两次后，只剩 `followup`。
- **环境信号只用来决定“什么时候说”，不用来当“说的理由”。** 最好的送达时机不是某个时间点，而是**你刚回到电脑前**。深夜那句“已经很晚了”可以破例穿透安静时段（安静时段是为了不吵醒你，而你明明醒着），但只在 app 在前台时，一晚最多一次，不说教。

**已删除：`miss_you`。** 沉默本身不是理由。她可以在下次见面时直接问那件事，但不提“你没回我”。

## 二、怎么开口

### 送达分三档

| 状态 | 做法 |
|---|---|
| **在场**（app 在前台，你没在打字或说话） | 直接在舞台上说 |
| **在旁边**（app 在后台） | 不出声。菜单栏图标轻轻呼吸一下，带一行字；你点开才说话 |
| **不打扰** | 先攒着 |

- **不打扰**：全屏、共享屏幕、麦克风正被别的 app 使用（基本等于在开会）、系统勿扰。
  - 前三个可以检测；系统的勿扰 / 专注模式没有公开 API，只能读一个需要完全磁盘访问权限的文件，不做。
- **攒着的话要有保质期**：送达前再判断一次“现在还要说吗”，因为你可能已经自己聊过这件事了。超过几个小时就丢掉，不要补发一条过时的关心。
- **桌面端的形态**：先在菜单栏跑通送达，再换成刘海小条。刘海条更有“她在”的感觉，但需要自绘无边框浮层（避开刘海、外接屏、全屏、多 Space），边界多。两者只换外壳，不改逻辑。
  - macOS 没有灵动岛的公开 API；刘海条是自己画的一条浮层，不是系统能力。

### 你没回应

她不重复。下次见面时直接问那件事本身，不说“那天你在忙吧”——指出“你没回我”本身就会给人一点需要解释的压力。

## 三、频率和节制

- 设置里的档位（不打扰 / 偶尔 / 经常）永远是**上限**，自适应只在档位以下调整。
- **降得快**：“没理”指她开口后你还没说过话。每多一次没理，立刻退一级。
  - 连续 2 次没理：只保留 `followup`。
  - 连续 3 次没理：只在你回来时才说。
- **升得慢**：你每回来和她聊一天，她恢复一级；同一天聊得再多也只算一级。不会因为一次回复就拉满。
- **“慢慢熟起来”不是说得更多，而是能为更小的事开口。** 刚认识时只为重要的事（面试、搬家）主动找你；熟了以后，一句余味也够格。总量不必变多，变的是理由的门槛。

## 四、背后怎么判断

拆成两步，人设不参与“该不该说”：

1. **判断**：一次便宜的结构化调用，不带人设。输入候选事件、最近对话和规则，输出“不说”或“说哪一件、为什么”。**大多数时候答案应该是“没有”。**
   - 每一种理由失败的方式不同，判断时各有一条专门的检验：跟进会过时，echo 会显得假，问候会变空洞。
   - 判断只看事实（`reason`），看不到给人设的说话指导（`guide`），免得被“怎么说”影响“该不该说”。
2. **生成**：人设只拿到选中的那一件事和说话指导，写一句话。

每次是不说、说了还是被回应，都记下来。既能用来调参数，也能让你看到“她为什么来找你”。

## 五、要守住的底线

写进规则，而不是只靠人设：

- **禁止**：让人内疚（“你都不理我了”）、制造缺失感（“我一直在等你”）、制造紧迫感、夸大她自己的情绪。
- **鼓励**：把你往现实生活里推一点——“今晚和朋友吃饭开心吗”，而不是“多陪陪我”。
- **可控**：一句话就能取消一件跟进（“别再问面试了”），也能说“这周别找我”。

这样的主动性才是温暖的，而不是黏人的。

## 六、落地顺序

- **P1（纯后端，风险低）** ✅：删 `miss_you`；`followup` 的取消和过期；底线写进提示；判断和生成拆开；自适应降频。
- **P2** ✅：抽取 `echo`；`rhythm` 改名（原来叫 `morning`，但下班、深夜的作息也会触发），理由写真实时段，能挂在今天的安排上。
- **P3（桌面端）**：菜单栏送达 → 刘海条；回到电脑前时送达；全屏和通话检测；送达时才合成语音。

## 已定的事

1. `miss_you` 删除。
2. 时段问候只在“经常”档位允许。
3. 送达先做菜单栏，再做刘海条。
4. 下次见面直接问那件事本身，不提沉默。
